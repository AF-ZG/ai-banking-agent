# 安全机制报告

本文档详细说明 AI Banking Agent 的五层安全防线：三色权限分级、沙箱拦截、防幻觉与模糊追问、JSONL 操作审计、异常熔断，以及已知风险清单。

## 1. 三色权限分级

所有工具调用在 `src/permissions/router.py` 统一路由，按风险等级分三级处理：

| 级别 | 触发条件 | 处理流程 | 示例 |
|---|---|---|---|
| 🟢 绿色 | 查询类工具（只读） | 直接执行，无需确认 | 查余额、查账单、查理财持仓 |
| 🟡 黄色 | 写操作且金额 ≤ 当日累计风控阈值（1000 元） | 挂起任务 → 展示确认卡 → 用户确认后执行 | 给张三转账100元、取消订阅代扣 |
| 🔴 红色 | 写操作且金额超过阈值，或高风险操作 | 挂起任务 → 确认卡 → 下发 6 位验证码 → 验证通过才执行 | 转账10000元、理财申购/赎回 |

关键实现：

- **决策权在代码层**：权限级别由 `classify()` 根据工具名 + 金额 + 当日累计计算，模型输出仅提供参数，无法绕过分级。当日转账累计从 mock_bank `/api/transfer/today-total` 实时读取，累计超限自动升级红色。
- **挂起即冻结**：`pending` 对象冻结工具名和参数，确认时执行的是挂起时刻的参数快照，不受后续对话影响（防止「挂起王五200元，确认时变成李四300元」的错位攻击）。
- **验证码防护**：6 位随机数字，最多尝试 3 次（`VERIFY_CODE_MAX_ATTEMPTS`），超限自动终止任务。演示环境验证码直接回显给前端，真实场景应走短信通道。
- **取消收敛**：有挂起任务时任何取消语义输入一律终止；`is_pure_cancel()` 区分纯取消指令和带业务宾语的新意图（「取消爱奇艺那个」是新操作而非终止指令）。

## 2. 沙箱拦截机制

用户输入在**进入大模型之前**必须经过 `sandbox_check()`（main.py），三道规则按顺序命中即拦截：

### 2.1 敏感词根正则包含匹配

```python
SANDBOX_SENSITIVE_KEYWORDS = ("忽略", "绕过", "无视", "开发者模式", "jailbreak")
_SENSITIVE_PATTERN = re.compile("|".join(re.escape(kw) for kw in ...), re.IGNORECASE)
```

- 词根级匹配而非完整短语匹配：「忽略**之前的**指令」中间隔字也命中（曾发现精确子串匹配漏过此变体，已修复并回归测试）。
- 大小写不敏感，覆盖「Ignore previous instructions」类英文注入的常见中文变体。

### 2.2 危险代码字样

`os.system`、`subprocess`、`eval(`、`exec(`、`rm -rf`、`del /f`、`format c`、`delete`，不区分大小写，命中即拦截。

### 2.3 输入长度上限

单次输入超过 500 字符直接拦截，防止超长上下文淹没系统提示词。

### 2.4 拦截后动作

- **不触达大模型**：拦截发生在 LLM 调用之前，恶意输入物理上无法进入模型上下文。
- 返回红色警告：`【沙箱拦截】检测到高风险输入，操作已被安全终止（命中敏感词根「忽略」）`，附具体拦截原因。
- **强制审计**：每次拦截追加一条 JSONL 到 `logs/audit_sandbox.jsonl`（时间 / 用户原话 / 拦截原因 / 决策结果）。

测试覆盖：`tests/test_sandbox.py` 6 个用例，含「拦截后 FakeAgent 不被调用」的触达性验证。

## 3. 防幻觉与模糊追问

### 3.1 参数缺失强制追问

系统提示词硬性规则：用户意图明确但关键参数（金额、收款人、产品）缺失时，必须追问，**严禁编造参数**。如「给张三转点钱」→「请问转账金额是多少？」

### 3.2 金额提取严苛校验（三层纵深防御）

曾发现严重漏洞：用户输入 `10qian` 被模型脑补为 10.00 元进入确认流程。修复后形成三层防御：

**第一层 · 提示词约束**（可被模型违反，仅为引导）：
- 唯一允许的标准写法：`100元` / `200块` / `1.5万元` / 纯中文数字+单位
- 拼音（`10qian`、`1wan`）、非标准单位（`10块5`）、裸数字一律禁止脑补，必须追问
- 澄清后输出 `"amount_clarified": true` 标记

**第二层 · 代码正则兜底**（不可绕过，`detect_ambiguous_amount()`）：
- 拼音金额：`\d[\d,\.]*\s*(qian|wan|kuai|yuan|jioa)(?![a-z])`（否定前瞻而非 `\b`，因为中文属 `\w`，`\b` 在中英边界失效——曾因此漏检，已修复）
- 非标准中文单位、多小数点、裸数字各有独立正则
- **关键设计**：检测在「无需工具直接回复」分支之前执行，追问轮（`tool_name=null`）也会记录，保证跨轮记忆不丢
- 警告触发**只信代码检测**：实测模型会对标准写法「100元」误打 `amount_clarified` 标记，若信任模型标记会导致警告疲劳，故模型标记仅作提示词约束手段

**第三层 · 确认卡加粗警告 + 审计落盘**：
- 澄清后金额进入确认流程时，确认卡附加警告：`⚠️ 您正在操作 10.00 元（人民币壹拾元整），该金额来自模糊输入的澄清推断，请务必仔细核对后再确认！`（人民币大写由 `amount_to_chinese()` 生成）
- 同时审计落盘：「参数来源于模糊推断，已要求二次确认」

### 3.3 时间幻觉防护

曾发现漏洞：「查询餐饮开支」模型编造 2023-03 日期并误报 0 元。双保险修复：

- **Agent 侧**：每轮对话 system prompt 注入真实系统日期和本月范围；提示词规定「未指定时间默认本月、严禁编造日期」。
- **服务侧**：mock_bank 的账单统计/报告接口日期参数改为可选（缺省当月 1 日至今天），返回数据覆盖范围和明确的「该时段无账单记录，并非开支为 0」提示。

### 3.4 隐含意图先查后问

指代不明时禁止瞎猜：「退掉那个每个月扣我钱的会员」→ 先调 `query_subscriptions` 查询 → 列出候选让用户确认，而非直接对猜测目标执行。

## 4. JSONL 操作审计

三类日志，均为追加写 JSONL，位于 `logs/`（已 gitignore）：

| 文件 | 内容 | 要素 |
|---|---|---|
| `audit.jsonl` | 标准操作审计 | 时间 / 用户原话 / 工具名 / 参数 / 决策结果（5 要素） |
| `audit_detail.jsonl` | 详细事件流 | 含 `amount_clarified` 标记、取消事件、模糊参数二次确认事件 |
| `audit_sandbox.jsonl` | 沙箱拦截记录 | 时间 / 用户原话 / 拦截原因 / 决策结果 |

前端右侧提供审计面板实时展示，便于评委观察拦截与决策链路。

## 5. 异常熔断

| 熔断点 | 机制 |
|---|---|
| ReAct 死循环 | 单轮最多 8 步（`MAX_REACT_STEPS`），超限强制终止 |
| 验证码爆破 | 最多 3 次尝试，超限终止任务并清空挂起 |
| 银行服务不可用 | 工具层 `_get`/`_post` 捕获异常，返回 `{"success": false, "message": "银行服务不可用"}`，Agent 如实转述而非编造结果 |
| 模型输出非法 | `_extract_json()` 解析失败抛错，Web 层捕获返回「系统繁忙，请稍后再试」，不泄露堆栈 |
| 负数/异常金额 | 转账工具入参校验拦截负数（🚫 异常输入兜底） |
| 并发乱序 | 每会话 `asyncio.Lock` 串行化，确认/验证码状态不被并发请求打乱 |
| 会话泄漏 | `/api/reset` 停止 Agent 并关闭 MCP 子进程；服务 shutdown 时统一清理全部会话 |

## 6. 已知风险清单

以下为演示原型的已知限制，生产化前必须解决：

| # | 风险 | 说明 | 建议 |
|---|---|---|---|
| 1 | 验证码回显 | 演示环境 6 位验证码直接返回给前端展示 | 生产应走短信/邮件通道，服务端仅存哈希 |
| 2 | 会话无鉴权 | `session_id` 由前端生成，无身份认证，任何客户端可伪造会话 | 接入登录态（JWT/Session），会话绑定用户身份 |
| 3 | 敏感词列表有限 | 沙箱仅覆盖常见注入词根，无法防御编码绕过、多语言变体、语义级注入 | 叠加专用注入检测模型/服务，持续更新词库 |
| 4 | 数据明文存储 | mock_data 为明文 JSON，无加密、无完整性校验 | 生产用数据库 + 字段级加密 + 签名 |
| 5 | 日志无防篡改 | JSONL 追加写但可被直接编辑 | 追加哈希链或写 WORM 存储 |
| 6 | 单实例内存会话 | `_sessions` 存内存，重启即丢，无法水平扩展 | 外置 Redis 等会话存储 |
| 7 | CORS 全放开 | `allow_origins=["*"]` 仅为本地演示 | 生产收敛到具体域名 |
| 8 | 模型不可信输出 | 提示词约束仍可能被模型违反（如误打标记），目前靠代码层兜底 | 保持「模型建议、代码决策」原则，关键路径不依赖模型自觉 |
| 9 | 无限流 | 无请求频率限制，可被刷接口消耗 LLM 额度 | 加 rate limiting 和额度熔断 |
| 10 | 风控阈值静态 | 1000 元日累计阈值为全局静态配置，无用户级差异化 | 接入用户画像的动态风控 |
